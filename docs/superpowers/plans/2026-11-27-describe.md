# Describe (step B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `copernicus-ems describe CODE` writes `<CODE>/description.json`: a checked it/en description of the activation and fields extracted from the official text with their quotes, made by Claude or a local OpenAI-compatible model; the demo shows it.

**Architecture:** Three library modules — `describe_input.py` (source text + aggregated facts, no model), `describe_checks.py` (pure validation of a model answer), `describe.py` (providers, retry, cache, file) in a new `[ai]` extra — then CLI/compose/Make, demo API + pages, docs.

**Tech Stack:** Python 3.12, `anthropic` SDK (structured outputs), httpx (local `/v1/chat/completions`), shapely (existing `geo`), pytest; llama.cpp server image; Next.js demo.

**Spec:** `docs/superpowers/specs/2026-11-27-describe-design.md`

## Global Constraints

- Output file `<directory>/<CODE>/description.json`, keys exactly: `activation`, `generated_at`, `provider` (`"claude"`|`"local"`), `model`, `prompt_version`, `inputs_hash`, `source`, `facts`, `description` (`{"it","en"}` or `null`), `reason` (string when description is null, else null), `places`, `rivers` (`[{name, quote}]`), `related_events` (`[{date, what, quote}]`), `casualties` (`{deaths, quote}` or `null`), `dropped` (`[{field, value, why}]`). Written via `.part` then rename. A shape change is a new version + message to limen-v3.
- Env: `COPERNICUS_EMS_LLM` (`claude`|`local`|unset), `COPERNICUS_EMS_LLM_URL`, `COPERNICUS_EMS_LLM_MODEL`, `COPERNICUS_EMS_CLAUDE_MODEL` (default `claude-opus-5-5`).
- Claude call: official `anthropic` SDK only (no OpenAI shim for Claude); `output_config={"format": {"type": "json_schema", "schema": ...}}`; beta `server-side-fallback-2026-07-01` with `fallbacks="default"` via `client.beta.messages.create`; check `stop_reason == "refusal"`; read API shapes from the claude-api skill docs (`python/claude-api/README.md`, `tool-use.md` structured outputs) — never guess.
- `[ai]` extra = `anthropic`; nothing outside `describe.py` imports it, and `describe.py` imports it lazily inside the Claude provider.
- Tests never call a real model or the network: local provider via `httpx.MockTransport`, Claude via an injected fake client.
- Never words judging an EMS map as wrong/error (it/en: sbagliat*, errore, wrong, error, mistake) in any user-facing text; radar candidates never called missed water.
- Only public EMS text and library numbers are sent to a model.
- `make check` green before each commit.

## Review Focus

- An answer whose quote differs only by whitespace/case from the source → kept; a quote not in the source → field dropped with `why` — Task 2.
- Italian description with "tre vittime" when the source says "three deaths" → accepted (numbers 0–20 in words, it/en) — Task 2.
- Second rejection → `description: null`, fields kept, cached; rerun without `--force` makes no model call — Task 3.
- Activation with no `reason` text → no model call, file with `description: null`, `reason: "no official text"` — Task 3.
- `describe --all` with one provider failure → others written, exit 1 — Task 4.

### Task 1: Input — official text and facts

**Files:** Create `src/copernicus_ems/describe_input.py`; Test `tests/test_describe_input.py`

**Interfaces — Produces:**
- `@dataclass(frozen=True) Source: code: str, name: str, reason: str, bulletins: list[dict[str, str]]` (title, url), `related: list[str]`; `as_dict()`.
- `read_source(code: str, directory: Path | None = None) -> Source` from `detail_path(code, directory)` (`results[0]`: `reason`, `infobulletins`, `relatedevents`); missing reason → `""`.
- `facts(code: str, directory: Path | None = None) -> dict[str, Any]`: activation name/category/event_time/countries and, per AOI name: `water_km2` (max over products, 2 decimals), `observed_km2` (max, 0 decimals), `first_map`/`last_map` (ISO dates), `sensors` (sorted), `maps`, and `radar` counts `{confirms, to_check, not_assessable}` read from `<CODE>/sentinel-1/*_quality.json` (40 m first, then newest, per product; plain JSON, no `[ml]`). Uses saved layers only (no network): `read_products` + the saved observed-event GeoJSON through the same functions `geo.summary` uses (`[geo]` extra).
- `allowed_numbers(facts, source) -> set[str]` and `allowed_names(facts, source) -> set[str]` helpers for Task 2 (all numbers as displayed strings; all names = AOI names, sensors, activation name words, capitalised words of the reason text).

- [ ] Step 1: failing tests on the saved fixture (`saved`/`data_dir` fixtures as in `tests/test_demo_api.py`, activation EMSR762): source fields; facts per AOI values match `geo.summary`; radar counts from hand-written quality files; no network (MockTransport that raises).
- [ ] Step 2: run → FAIL. Step 3: implement. Step 4: `make check`. Step 5: commit `feat(describe): official text and facts of an activation`.

### Task 2: Checks of a model answer

**Files:** Create `src/copernicus_ems/describe_checks.py`; Test `tests/test_describe_checks.py`

**Interfaces — Produces:**
- `ANSWER_SCHEMA: dict` (JSON schema: `description {it,en}`, `places`, `rivers`, `related_events`, `casualties`; `additionalProperties: false`).
- `@dataclass Checked: description: dict[str,str] | None, places, rivers, related_events, casualties, dropped: list[dict], problems: list[str]`.
- `check(answer: dict, source: Source, facts: dict) -> Checked`: fields with quotes not found in `source.reason` (normalised: casefold, collapse whitespace, unify quotes/dashes) → dropped with `why`; description problems: numbers (digits; number words 0–20 it/en; "day month" dates it/en) not in allowed sets (tolerance: equal after rounding to the precision written); capitalised words not at sentence start not in `allowed_names` or allow-list (`ALLOWED_NAMES`: Italia, Italy, Copernicus, Sentinel-1, Sentinel-2, Europa, Europe, EMS, month names it/en, weekday names); forbidden words (`FORBIDDEN`: it/en list incl. sbagliat*, errore, errata, wrong, error, mistake, mancat* acqua, missed). Any problem → `description` None in `Checked` and `problems` filled.
- [ ] Step 1: failing tests: valid answer kept; quote case/space variant kept; invented quote dropped; invented number rejected; "tre vittime" vs "three deaths" accepted; "2 maggio 2023" vs "2 May 2023" accepted; unknown proper noun rejected; forbidden word rejected; schema shape.
- [ ] Step 2–5 as usual; commit `feat(describe): checks of a model answer`.
